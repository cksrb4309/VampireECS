# VampireECS 기획 초안

## 1. 프로젝트 목적

`VampireECS`는 단순히 Vampire Survivors 류 게임을 만드는 프로젝트가 아니라,
`DOTS/ECS 기반 전투 루프를 높은 성능으로 운용하기 위한 실험이자 프로토타입`입니다.

핵심 목표는 다음과 같습니다.

1. 대량의 적, 지속적인 공격 판정, 반복적인 상태 갱신을 ECS 구조로 안정적으로 처리한다.
2. 전투-경험치-레벨업-강화 선택으로 이어지는 생존 액션 루프를 하나의 일관된 구조로 정리한다.
3. 성능과 확장성을 고려한 전투 아키텍처를 먼저 검증한 뒤 콘텐츠를 늘린다.

## 2. 게임 한 줄 정의

플레이어가 끊임없이 몰려오는 적을 상대로 생존하며, 레벨업마다 능력 또는 강화 선택지를 얻어 전투 빌드를 성장시키는 탑다운 생존 액션.

## 3. 현재 게임 비전

### 플레이 감각

- 짧은 입력으로 즉시 반응하는 경쾌한 이동
- 적이 계속 몰려오는 압박감
- 공격 수단이 늘어나며 전투 밀도가 점점 올라가는 성장감
- 레벨업 시 잠시 정지하고 빌드 방향을 선택하는 전략성

### 기술 감각

- 전투 로직은 ECS 중심
- 화면/UI/입력은 ECS 바깥 브리지 계층
- 콘텐츠를 늘려도 구조가 버티는 형태
- 성능 민감 구간은 Burst/job 친화적으로 유지

## 4. 타겟 경험

- 많은 적이 동시에 존재해도 전투가 무너지지 않아야 한다.
- 공격 종류가 늘어나도 전투 흐름이 단순한 규칙으로 유지되어야 한다.
- 레벨업 선택이 즉각적으로 플레이 스타일 차이를 만들어야 한다.
- 현재는 시네마틱 연출보다도 전투 응답성, 밀도, 시스템 일관성이 우선이다.

## 5. 코어 루프

1. 플레이어가 이동하며 적을 피하거나 포지셔닝한다.
2. 플레이어의 공격이 자동 또는 조준 기반으로 적에게 피해를 준다.
3. 적은 플레이어를 추적하며 계속 스폰된다.
4. 적이 죽으면 경험치를 얻는다.
5. 일정 경험치에 도달하면 레벨업한다.
6. 게임이 일시정지되고 3개의 보상 후보가 제시된다.
7. 플레이어가 강화 또는 해금을 선택한다.
8. 선택 결과가 ECS 컴포넌트에 반영되고 전투가 계속된다.

이 루프가 현재 프로젝트의 가장 중요한 검증 대상이다.

## 6. 전투 설계 초안

### 플레이어

- 탑다운 시점 기준 2D 입력으로 평면 이동
- 마우스 위치를 월드 좌표로 환산해 조준
- 공격은 조준 기반 사수형 무기와 자동/주기형 공격으로 확장

### 적

- 플레이어 주변 반경에서 생성
- 플레이어를 향해 추적
- 너무 멀어진 적은 다시 플레이어 근처로 재배치
- 현재는 소수 적 타입 기반 테스트 단계

### 공격 방식

#### 1. Shooter

- 마우스 방향으로 발사
- 발사 속도, 데미지, 투사체 속도, 지속 시간, 발사 개수 강화 가능
- 다중 발사 시 부채꼴 퍼짐

#### 2. Aura

- 플레이어 중심 범위 피해
- 공격 속도, 반경, 데미지 강화 가능
- 공간 분할 인덱스를 이용해 범위 내 타깃 탐색

#### 3. Chain Lightning

- 자동 타깃 기반 즉발 연쇄 공격
- 첫 타깃 탐색 후 반경 내 다른 적으로 점프
- 점프 수, 점프 반경, 피해 유지율 강화 가능

#### 4. Meteor Strike

- 자동 타깃 기반 지연 폭발 공격
- 경고 후 낙하, 원형 범위 폭발
- 메테오 수, 낙하 시간, 폭발 범위, 산개 범위 강화 가능

#### 5. Black Hole

- 자동 타깃 기반 지속 필드 공격
- 지정 지점에 블랙홀을 생성해 적을 흡인하고 지속 피해를 준다
- 지속시간, 반경, 흡인력, 틱 데미지 강화 가능

### 피해 처리

- 직접 체력을 깎지 않고 `DamageEvent`를 생성
- 별도 시스템에서 체력 감소, 사망 태그 부여, 데미지 텍스트 이벤트 생성
- 이벤트 엔티티 기반 흐름으로 시스템 결합도를 낮춤

## 7. 성장 설계 초안

### 경험치

- 적 처치 시 경험치 이벤트 생성
- 플레이어 경험치가 누적됨
- 요구 경험치를 넘으면 레벨업
- 레벨이 오를수록 필요 경험치 증가

### 레벨업 보상

- 레벨업 시 시간 정지
- 3개의 선택지 제공
- 선택지는 현재 보유 상태와 최대 스택 여부에 따라 구성
- 선택지 부족 시 더미 선택지로 채움

### 능력 타입

#### 1. 해금형 능력

- 새로운 공격 수단을 열어줌
- 예: Aura, Chain Lightning, Meteor Strike, Black Hole
- 보통 1회성

#### 2. 스탯 강화형 능력

- 이미 존재하는 전투 요소를 강화
- 예: 데미지, 공격 속도, 범위, 개수, 지속시간
- 다회 스택 가능

### 등급

- 브론즈 / 실버 / 골드
- 레벨업 시 랜덤 등급 부여
- 등급에 따라 강화량 범위가 달라짐

## 8. 현재 데이터/스탯 구조

현재 공격 능력은 `기본값`과 `강화값`을 분리하는 구조로 정리되어 있다.

- `Unlock...Config`
  - 능력 해금과 기본 수치 정의
- `...BaseStatsData`
  - 런타임 기본 성능
- `...StatsConfig`
  - 레벨업으로 더해지는 강화량
- `...StatsData`
  - 누적된 강화값
- `CombatStatsData`
  - 모든 능력에 공통으로 곱해지는 전역 전투 배율

이 구조의 목적은 다음과 같다.

- 능력마다 다른 기본 성능을 유지한다
- 강화 설명을 일관된 규칙으로 표시한다
- 밸런스 조정 시 “무기 기본 성능”과 “레벨업 증가량”을 분리해서 다룬다

## 9. 현재 콘텐츠 기준 해석

현재 프로젝트는 “완성된 게임 콘텐츠”보다는 “전투 구조 검증”에 맞춰져 있다.

확인 가능한 범위는 다음과 같다.

- 테스트 씬 1개
- 플레이어 1종
- 적 1종
- Shooter
- Aura
- Chain Lightning
- Meteor Strike
- Black Hole
- 기본 전투 스탯 강화
- 레벨업 3지선다 UI

즉, 현재는 아래 질문에 답하기 위한 단계로 보는 것이 맞다.

- ECS 전투 루프가 안정적으로 도는가
- 성장 구조가 자연스럽게 연결되는가
- 적 수가 증가해도 구조가 버티는가
- 이후 적/무기/패턴을 늘려도 시스템이 유지되는가

## 10. 시스템 설계 철학

### 왜 DOTS/ECS인가

이 프로젝트에서 ECS는 단순한 기술 선택이 아니라 목적 그 자체에 가깝다.

- 적 수 증가에 대응하기 쉽다
- 전투 데이터를 연속 메모리 구조로 다루기 좋다
- 시스템 분리를 통해 전투 흐름을 예측 가능하게 유지할 수 있다
- 스폰, 이동, 판정, 피해, 정리 단계를 그룹 단위로 제어할 수 있다

### 무엇을 ECS에 남길 것인가

- 전투 상태
- 이동 상태
- 공격 상태
- 피해 이벤트
- 경험치와 레벨업 요청

### 무엇을 브리지로 둘 것인가

- 입력
- UI 갱신
- 카메라
- VFX/씬 객체와의 연결

이 분리는 성능과 개발 생산성을 동시에 확보하려는 선택으로 본다.

## 11. 현재 밸런스 해석

현재 수치들은 본격 밸런스라기보다 테스트 수치일 가능성이 높다.

- 플레이어 체력이 매우 높음
- 적 체력과 경험치 보상이 단순함
- 능력 수가 늘었지만 적 조합과 세션 규칙은 아직 단순함

따라서 지금 단계의 밸런스 목표는 “재미 최적화”보다도 “시스템이 안정적으로 연결되는지”에 가깝다.

## 12. 추후 기획 확장 방향

### 전투 확장

- 적 타입 추가
- 원거리 적 / 특수 적 / 돌진 적
- 보스 또는 엘리트 적

### 성장 확장

- 능력 간 시너지
- 선행 조건을 활용한 빌드 분화
- 해금형과 강화형 보상의 풀 확장

### 세션 구조 확장

- 시간 경과 기반 웨이브 변화
- 클리어 조건 / 실패 조건
- 재도전 루프

### 메타 확장

- 영구 해금
- 로비 또는 진척도
- 기록 및 성능 리포트

## 13. 현재 우선순위 제안

현재 프로젝트 목적을 기준으로 하면 우선순위는 다음이 적절하다.

1. 전투 루프 안정화
2. ECS 성능 병목 확인
3. 적 타입과 능력 타입 최소 확장
4. 레벨업 선택 의미 강화
5. 세션 시작/종료 루프 정리
6. 그 이후 콘텐츠 양 확장

## 14. 성공 기준 초안

이 프로젝트가 현재 단계에서 성공했다고 볼 기준은 다음과 같다.

- 플레이어 이동, 적 스폰, 공격, 피해, 경험치, 레벨업이 끊김 없이 이어진다.
- 적 수가 늘어도 프레임 저하가 과도하지 않다.
- 능력 선택이 전투 방식의 차이를 실제로 만든다.
- ECS와 UI/브리지 계층의 책임 분리가 유지된다.
- 신규 적/능력 추가가 기존 구조를 크게 해치지 않는다.

## 15. 현재 상태 한 줄 요약

`VampireECS`는 “대량 전투를 견디는 ECS 전투 구조”를 먼저 만들고, 그 위에 생존 액션 콘텐츠를 쌓아 올리기 위한 기술 중심 전투 프로토타입이다.
